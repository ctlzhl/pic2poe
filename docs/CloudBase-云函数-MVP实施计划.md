# 照片有话说：CloudBase MVP 实施计划与现状

状态：早期实施计划已落地并持续迭代；以下按 2026-10-05 工作区代码更新。它不证明云端已部署同一版本；部署步骤及线上验收以 [P1 云端配置与验收](./P1-云端配置与验收.md) 为准。

## 目标与技术边界

目前的核心闭环是「上传一张照片 → 选择五言绝句、图片点评或配图文案 → 创作任务 → 结果 → 保存分享」。小程序、CloudBase 云函数、文档数据库和云存储构成现有实现；不使用 NestJS、MySQL、Redis 或 BullMQ。`poemRecords` 是旧版数据，不迁入新版私有集合。虚拟支付与渠道归因仅有独立设计或讨论，未接入此闭环。

## 当前数据与访问契约

| 集合 | 责任 |
| --- | --- |
| `users` | 当前用户头像与昵称资料 |
| `imageAssets` | 图片暂存、原图、标准创作图、缩略图及清理状态 |
| `creationDrafts` | 照片、创作类型和用户补充信息的任务输入 |
| `creationTasks` / `creationAttempts` | 可轮询的任务状态和每次执行记录 |
| `works` | 成功作品；同图再次创作会产生另一份作品 |
| `shareCards` | 分享成品图、不可猜测的 `shareToken` 与公开快照 |
| `blogHomeCache` | 最近 50 篇公开博客文章的 `latest-fifty` 快照 |

新版集合仅由云函数读写。用户私有函数依据调用者 `OPENID` 校验归属；公开分享由 `getSharedWork` 校验 `shareToken`，博客由 `getBlogPosts` 返回公开数据。小程序不直接读取这些业务集合。

## 图片、任务与安全

1. 客户端一次只选择一张 JPG、PNG 或 WebP，最大 6MB；`createImageUpload` 分配暂存路径，客户端上传，`prepareImage` 校验文件、图片内容安全和一次性资产归属，再生成标准创作图和缩略图。客户端会在进入创作表单前做图片预处理，以减少云端解码与传输耗时。
2. 原图与暂存文件是短期资产，应用清理函数负责回收；云存储 `original/`、`staging/` 的两天生命周期规则是兜底，须在控制台单独配置与核验。标准创作图、缩略图随仍在引用它们的作品保留。删除一份共享同图的作品，不应破坏另一份作品。
3. `createCreation` 创建草稿和任务并实施频控；创作页转入「创作中」后直接调用 `runCreation`，每分钟定时触发器兜底派发。客户端轮询 `getCreation`；失败可经 `retryCreation` 重试。`recoverStuckTasks` 回收滞留任务，`cleanupExpiredAssets` 每 15 分钟清理到期资产。
4. 状态为 `queued → analyzing → generating → validating → succeeded/failed`。同一任务领取和完成必须防止重复执行、超时或迟到结果覆盖。模型使用固定快照 `qwen3.7-flash-2026-07-15`；密钥及可调参数只在云函数环境变量中配置，模型名不由客户端指定。
5. 图片上传、用户补充文字、模型输出及公开分享前均按相应路径执行内容安全校验。违规或接口不可用时不得将未通过内容作为可创作资产或公开分享内容放行。

## 当前页面与分享

- 首页展示创作入口和「随便看看」最近三篇博客；创作页没有待创作照片时展示缺省图，离开后返回不保留上次上传的草稿。
- 「创作中」展示真实任务状态、失败重试和成功后 3 秒跳转；结果页承载三种作品，并以一行三列展示「重新创作」「换图再写」「保存分享」。没有独立分享页。
- 分享图在结果页静默准备，点击「保存分享」调起微信原生图片分享菜单。五言绝句横图/方图上诗下图，图评和文案横图/方图上图下文；竖图统一左图右文。照片等比例展示，画布随原图比例与内容高度自适应。
- 「我的」使用头像和昵称标准控件，并缓存当前页面会话中的资料；「我的作品」按每页 10 条加载，图片资产按页批量查询。首页、博客列表、博客文章详情与公开分享页均可按各自能力分享。
- 博客每日刷新最近 50 篇快照与封面。同步任务每次最多处理 16 张待更新封面、分批并发 4 张；读取快照时换取云存储临时链接，文章缺少封面时保留占位，失败时尽量沿用旧封面。旧封面退出快照后保留 7 天，定时清理前再次核对引用；超过快照范围或筛选类目不足时回源 WordPress。

## 阶段回顾与验收边界

| 阶段 | 当前状态 | 仍需现场验证的内容 |
| --- | --- | --- |
| P0 图片与私有数据基线 | 已在代码中实现 JPG/PNG/WebP 和私有云函数数据访问 | 云端集合权限、存储生命周期和真机格式边界 |
| P1 上传与任务 | 已实现图片暂存、处理、任务轮询、超时和重试 | 不同网络与设备上的耗时、内容安全调用权限 |
| P2 三类创作 | 已实现三类输出与结果页 | 云端模型配置、真实照片质量和审核反馈 |
| P3 作品与分享 | 已实现分享卡、小程序码、作品列表与删除 | 真机原生分享、扫码、分享失效及同图多作品删除 |
| P4 上线加固 | 频控、清理、博客缓存等持续迭代 | 部署版本、定时触发器、成本告警与回归验收 |

工作区代码、自动测试与云端实际版本是不同层次。部署函数、创建数据库权限/索引和定时触发器后，仍需真机验收；不要以本地通过替代线上生效结论。

## 架构升级触发条件

当云函数并发、任务积压、执行时限或运营批处理确实成为瓶颈，再评估云托管和队列 Worker。迁移时保留作品、任务、资产和分享凭证的外部契约；这不是当前已实施的架构。
