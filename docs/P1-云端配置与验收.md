# P1：云端配置与验收

本说明只针对新版“照片有话说”P1。不要修改或复用旧版 `poemRecords`、`generatePoem`。

## 1. 创建新版集合并收紧权限

在云开发控制台的“数据库”中，逐一新建下列集合：

```text
users
imageAssets
creationDrafts
creationTasks
creationAttempts
works
shareCards
blogHomeCache
```

每个集合的权限都选择“仅云函数/管理员可读写”（界面文字因开发者工具版本可能略有不同）。目标是：小程序客户端不能直接读取或写入这些集合。用户私有数据仍须经过云函数中的 `OPENID` 归属校验；公开博客快照仅由 `getBlogPosts` 对外返回，不包含用户数据。

`blogHomeCache` 保存最近 50 篇公开博客文章的列表快照，固定文档 ID 为 `latest-fifty`；它同样由云函数独占读写，无需业务索引。封面文件存于云存储 `blog/covers/`。快照保留源站封面 URL 和已缓存的云存储文件 ID，但不保存会过期的临时链接。先创建集合，再部署 `getBlogPosts` 并运行一次定时同步。快照尚未建立时，首页和列表暂时回源 WordPress；同步失败时保留已有快照与可用封面，批量同步可能逐批更新进度，不应假定所有 50 篇在同一次执行中全部完成。旧的 `latest-three` 文档不再读取，暂时留存即可。

快照中的 `coverCleanup` 保存已替换或已移出最近 50 篇的旧封面文件 ID，至少等待 7 天。每日同步任务在删除前再次读取当前快照，仍被引用、未到期或非 `blog/covers/` 路径的文件都不会删除；云存储删除失败会留待下次定时执行。不要对整个 `blog/covers/` 设置固定 7 天生命周期，否则仍在使用的封面也会被删除。部署后可用一篇更换封面的测试文章检查：旧文件先进入 `coverCleanup`，到期且不再被引用后才从云存储移除。

建议创建以下业务索引：

| 集合 | 索引字段 | 用途 |
| --- | --- | --- |
| `imageAssets` | `expiresAt` 升序 | 定时清理过期资产 |
| `creationTasks` | `userId` 升序、`idempotencyKey` 升序 | 防止重复提交 |
| `creationTasks` | `userId` 升序、`status` 升序 | 拒绝同一用户的并行任务 |
| `creationTasks` | `status` 升序、`deadlineAt` 升序 | 回收超时任务 |
| `works` | `userId` 升序、`createdAt` 降序 | 我的作品列表 |
| `shareCards` | `workId` 升序、`userId` 升序、`contentHash` 升序、`status` 升序、`templateVersion` 升序 | 复用同一作品的分享成品图 |
| `shareCards` | `shareToken` 升序、`status` 升序 | 按分享凭证读取公开作品快照 |
| `shareCards` | `status` 升序 | 回收已撤销分享图 |

### Sharp 云函数的部署前置条件

`prepareImage` 与 `createShareCard` 使用 Sharp，且配置为不在云端重新安装依赖。每次在**新的电脑、干净工作目录或更新 Sharp 后**部署前，都要在下列两个目录分别执行一次（不要把 `node_modules` 提交到 Git）：

```bash
cd cloudfunctions/prepareImage
npm install --include=optional --os=linux --cpu=x64 --libc=glibc

cd ../createShareCard
npm install --include=optional --os=linux --cpu=x64 --libc=glibc

cd ../..
```

随后再执行上方对应函数的部署命令。这样打包进云函数的是 Linux x64 的 Sharp 二进制，避免本机 macOS 依赖被上传后在 Node.js 20 云端无法加载。

如果此前尚未部署全部 P1 函数，则依次部署：

```bash
tcb fn deploy createImageUpload -r ap-shanghai
tcb fn deploy prepareImage -r ap-shanghai
tcb fn deploy createCreation -r ap-shanghai
tcb fn deploy runCreation -r ap-shanghai
tcb fn deploy getCreation -r ap-shanghai
tcb fn deploy getWork -r ap-shanghai
tcb fn deploy listWorks -r ap-shanghai
tcb fn deploy deleteWork -r ap-shanghai
tcb fn deploy retryCreation -r ap-shanghai
tcb fn deploy recoverStuckTasks -r ap-shanghai
tcb fn deploy cleanupExpiredAssets -r ap-shanghai
tcb fn deploy createShareCard -r ap-shanghai
tcb fn deploy getSharedWork -r ap-shanghai
```

部署后确认 `runCreation`、`recoverStuckTasks` 与 `cleanupExpiredAssets` 的“触发器”中分别出现每分钟、每分钟与每 15 分钟任务。

博客缓存改为每日同步：`cloudbaserc.json` 为 `getBlogPosts` 声明 `refresh-blog-daily`，Cron 为 `0 0 3 * * * *`，函数超时为 120 秒。部署新代码后，用 `tcb fn detail getBlogPosts -e cloud1-8gefec0p0d1f809d --json` 核对云端触发器；控制台显示“暂无数据”不能单独证明触发器不存在。如确实缺少每日触发器，可执行 `tcb fn trigger create getBlogPosts --trigger-name refresh-blog-daily --cron "0 0 3 * * * *" -e cloud1-8gefec0p0d1f809d`，再用 `detail` 核验。只有确认旧的 `refresh-home-blog-every-5-minutes` 仍在运行时才删除它；不要删除函数或 `blogHomeCache` 集合。

首次上线后，在云函数控制台用 `{"Type":"Timer","TriggerName":"refresh-blog-daily"}` 手动测试一次，确认返回 `ok: true`、`count` 不超过 50；随后检查 `blogHomeCache/latest-fifty` 和云存储 `blog/covers/`。首页应从快照显示三篇文章，未筛选列表前五页（每页 10 篇）应使用同一快照；类目筛选在快照覆盖范围内也优先读快照，不足部分或翻过 50 篇后才实时读取 WordPress。每次同步最多处理 16 张待更新封面，按 4 张一批执行；首次补齐大量封面可能需要重复同步。封面临时链接由函数在读取快照时换取，小程序本地首页缓存只保留 30 分钟，避免过期链接导致空白。若文章本身既没有特色图也没有正文图片，展示占位样式；若封面同步失败，保留该文章上次成功缓存的封面。

## 3. 小程序验收

1. 微信开发者工具重新编译小程序，确认环境初始化为 `cloud1-8gefec0p0d1f809d`。
2. 选择一张不超过 6MB 的 JPG、PNG 或 WebP；页面应显示“图片已准备好”。
3. 选择“五言绝句 / 图评 / 文案”任一类型，点击“开始创作”。
4. 在“正在创作”页停留 10 秒，应只出现一次“正在努力创作中”。未配置模型环境变量时，任务会安全失败并提示创作服务尚未准备好；配置完成后才会进入真实模型调用。
5. 点击“再试一次”，`attemptNumber` 应增加，且不用再次上传图片。
6. 分别测试超过 6MB 的文件、HEIC 和伪装成图片的损坏文件，均不应创建可创作资产。

### 内容安全补丁的部署与验收

仅部署本轮内容安全补丁时，按下列顺序更新五个函数，确保各目录的 `config.json` 一起上传：

```bash
tcb fn deploy prepareImage -r ap-shanghai
tcb fn deploy createCreation -r ap-shanghai
tcb fn deploy runCreation -r ap-shanghai
tcb fn deploy createShareCard -r ap-shanghai
tcb fn deploy getSharedWork -r ap-shanghai
```

其中 `prepareImage` 与 `createShareCard` 仍需按上文先准备 Linux x64 的 Sharp 依赖。新权限分别是图片检测 `security.imgSecCheck`、文字检测 `security.msgSecCheck`；如出现 `-604101`，先核对部署包中的 `config.json`，再等待云调用权限缓存生效，不能绕过检测放行。

- 上传图片时，`prepareImage` 在资产变为 `ready` 前调用微信图片检测；违规或接口异常都不创建可创作资产。
- 点击开始创作时，`createCreation` 对地点和补充文字调用微信新版文字检测；旧任务在 `runCreation` 中补检图片与草稿，生成结果写入 `works` 前再检一次文字。
- `createShareCard` 在上传并公开新分享图前，另对最终成品图（原图、文字和小程序码的合成结果）调用微信图片检测；已有分享图缺少成品图复检标记时，先下载成品复检，再允许复用。违规或接口异常均不得发布。
- 旧作品生成分享卡时还会补检原图缩略图和作品文字。`getSharedWork` 只返回作品内容与成品图均通过检测的分享快照。部署新访问校验后，尚未完成成品图复检的旧分享码会暂时不可访问；作品所有者重新打开结果页并复检通过后，原分享码可继续使用。因此应先部署 `createShareCard`，再部署 `getSharedWork`，并安排旧分享码回归验收。
- 在真机上用正常图片和文字完成一轮上传、创作、分享，核对云函数日志与资产/作品安全状态；再用微信提供的检测测试样例确认被拦截时只显示“内容含违规信息”的简短提示。微信接口不可用时应提示稍后重试，不能进入分享页。

P1 已包含上传、任务、超时和重试；内容生成与类型化结果依赖下列 P2 环境变量。不要把任何 API Key 写入小程序或 Git：


## 5. P3 分享配置与验收

`shareCards` 也必须配置为“仅云函数/管理员可读写”。公开访问不直接读取数据库，而是只通过 `getSharedWork` 校验不可猜测的分享凭证后返回公开作品快照；不要把 `works` 或 `imageAssets` 改成公开读。

分享图使用云调用生成带参小程序码。`createShareCard/config.json` 已声明 `wxacode.getUnlimited` 的 OpenAPI 调用权限；该文件必须随函数一起部署，否则云端会返回 `-604101`。联调阶段可不配置 `WXACODE_ENV_VERSION`，默认生成开发版小程序码；提交正式版前，在 `runCreation` 之外的 `createShareCard` 环境变量中设置：

```text
WXACODE_ENV_VERSION=release
```

若环境的云调用权限仍返回 `-604101`，函数会自动回退到微信服务端小程序码接口。此时在 **createShareCard** 的云函数环境变量中仅配置以下两项（不要写入代码、`cloudbaserc.json` 或数据库）：

```text
WECHAT_MINIPROGRAM_APP_ID=你的小程序AppID
WECHAT_MINIPROGRAM_APP_SECRET=你的小程序AppSecret
```

验收：打开一份已完成作品，等待分享成品图出现；可保存到相册、通过“发给好友”转发，并在第二个微信账号打开后看到只读作品。朋友圈分享请在真机右上角菜单验证；开发者工具不提供完整的朋友圈分享验证。

## 6. 博客与微信资料授权配置

- 部署 `getBlogPosts` 与 `userProfile` 后，新建私有集合 `users`，保持“仅云函数/管理员可读写”。`userProfile` 仅以当前调用者的 `openid` 作为文档 ID 保存昵称和头像，客户端不直接读写该集合。
- 云函数权限规则保留默认登录限制，但允许首页匿名加载博客：

```json
{
  "*": { "invoke": "auth != null" },
  "getBlogPosts": { "invoke": true }
}
```

- 在小程序后台的“开发管理 → 开发设置 → 服务器域名”中，将 `https://shengxiluo.me` 加入 `downloadFile 合法域名`，用于文章封面和正文图片。博客数据由云函数读取 WordPress REST API，不需要在客户端配置 `request 合法域名`。
- 首次进入“我的”会展示头像选择与昵称输入；用户点击头像时使用 `chooseAvatar`，点击昵称时使用 `type="nickname"`。头像上传到 `users/{openid}/profile/` 后由 `userProfile` 保存文件 ID；若用户不填写资料，不影响首页浏览和创作功能。当前页面会话复用已加载资料，后台刷新间隔为 30 分钟；切换底部导航后不应每次重新显示登录加载态。

## 7. P4 上线前加固

- 新创作限制为每位用户 10 分钟 4 次、24 小时 20 次；同一任务最多生成 3 次。数值在 `createCreation` 与 `retryCreation` 中实施，避免模型调用被滥用。
- `works`、`imageAssets`、`creationDrafts`、`creationTasks`、`creationAttempts`、`shareCards` 均保持“仅云函数/管理员可读写”。小程序仅能经云函数读取自己的作品；公开分享仅能经不可猜测的 `shareToken` 读取快照。
- 删除作品会先撤销关联分享凭证，再删除关联的任务、草稿和分享图。若同一图片仍被其他作品引用，会保留图片资产；只有最后一份引用被删除时才回收原图、创作图和缩略图。存储删除短暂失败时由现有定时清理函数在后续轮次回收，已撤销的分享链接不再可打开。
- 上线正式版前，在 **createShareCard** 的环境变量中设置 `WXACODE_ENV_VERSION=release`。保留 `WECHAT_MINIPROGRAM_APP_ID` 与 `WECHAT_MINIPROGRAM_APP_SECRET` 仅在云函数环境变量中，绝不写入代码、数据库或版本库。
- 真机验收须覆盖：JPG/PNG/WebP、HEIC 的友好提示、失败任务重试、作品删除、好友分享和扫码进入。开发者工具不等同于朋友圈和扫码的最终行为。
- 在云存储中为 `original/` 和 `staging/` 分别配置生命周期规则：对象创建 **2 天后删除**。这是应用清理任务的兜底；创建后上传一张测试图片，并在控制台确认两条规则均能命中对应前缀。
